# 第三阶段交付

## 已明确的接口

新增九类 Protocol：环境、任务、机器人、场景、规划、预检、执行、记录与能力检查。新增第一版 Schema，定义 14 类公开数据包，写清必填字段、形状、单位、坐标、时间索引、数据来源和结果含义。

数据结构和方法职责分别位于 [DATA.md](interfaces/DATA.md) 与 [SERVICES.md](interfaces/SERVICES.md)。接口代码位于 `src/graspgen_libero_bridge/contracts/`；Schema、能力要求和样例位于 `contracts/`。

## 当前 LIBERO 的参考

11 个源码锚点对应九类接口，指出哪些方法已存在、哪些需要包装，以及仍然直接依赖 MuJoCo、LIBERO 或 Panda 的地方。参考样例从原成功轨迹导出，没有运行新的环境或模型，没有假造旧记录未保存的标定、点云时间或目标区域。

所有 130 条旧结果另作规范化映射，官方成功、完整管线成功和排除已知顺序问题后的候选成功仍是 88/86/85。训练审核状态独立记录，不把 code policy 标签当作 VLM 决策。

## 可执行检查

新增离线 Schema、语义和上下文检查，覆盖来源混用、米制和坐标、矩阵有效性、关节顺序、任务引用、场景尺寸、计划起点、碰撞几何引用、预演恢复、动作/状态及关键点对齐。

能力检查单独报告缺失条件；结构有效的样例不会因此被宣称可执行。新测试和原测试一起做 CPU 回归，验证记录保存在 `migration/phase3/`。

## 未改动的运行范围

第二阶段已验证的 71 个代码及配置文件保持原样；原 39 个文件的机械迁移和 1040 组有效配置仍可核对。现有驱动没有改成通过新 Protocol 调用，策略顺序、规划和控制算法、参数、权重及原历史结果不变。

本阶段不实现或运行其他 benchmark，不启动 GPU 轨迹，不发布新的成功率。第四阶段将面向外部接入方写实施指南；实际运行链按统一接口重接和具体环境适配仍须单独实现、验证，不能由接口定义通过推导出已接通。

# r13：修正迁移衔接，重跑原 22 项抓放候选

日期：2026-11-12。r10 保留为旧记录，r13 是独立修复版本，不用新结果覆盖旧失败。r13 actor 指纹为 `d0d490639735da7c297550f2f4f4cb8446d8b69809422bab5c1c894a0cd428ff`，冻结代码提交为 `c81430dc9a211848fb300d0b1bab814c01069fb9`。

## 已修正的差异

| 项目 | r10 的差异 | r13 的处理 |
| --- | --- | --- |
| 持物登记 | 局部 MuJoCo 已按持物预演，但向 cuRobo 登记附件延后到抬升成功后；4 个失败的抬升回退记录均显示未附着 | 在抬升规划前登记附件，抬升保持后再按实测位姿刷新；每次保存 `PRE_LIFT_CONTEXT.json` |
| 持物刷新 | 原版在抬升保持后显式 detach/attach 更新相对位姿，r11 首批漏掉 detach | 刷新规划几何时先 detach 再 attach，物理夹爪持续闭合；增加严格 worker 协议回归与 GPU 接口验证 |
| 离开源支撑 | 全局抬升回退没有传递原版的源支撑许可 | 合并初始及闭合后的实际接触，过滤为场景中真实的支撑几何，仅在全局抬升回退传递；原生完整路径检查仍拒绝机器人/环境碰撞 |
| 放置朝向 | 原版容器放置默认最多 4 个物体朝向，映射后的列表没有保留该上限 | 从原 LIBERO 有效默认值读取并验证统一上限，按原顺序保留最多 4 个朝向；原搬运高度/偏航/放置算法继续复用 |
| 相同起点反复拒绝 | 3 个超时任务从相同关节起点分别得到 157、120、36 次全局无效起点拒绝 | 仅对完全相同的完整场景、机器人/手指状态、附件及接触配置复用无效起点结果；每个目标仍执行原生局部回退。状态、场景或接触配置改变后重查，不缓存目标相关的 IK 失败 |
| 结果保存 | 有限放置搜索失败的细节含 numpy 矩阵，旧 RESULT writer 无法写入 | 复用原生递归矩阵/标量转换与原子 JSON 保存，增加两个真实 driver 失败出口回归检查 |
| 运行预算 | 原 LIBERO 单物体抓放允许 1200 秒，本轮 r10 只有 900 秒 | 统一恢复 1200 秒总上限，其中 1190 秒用于工作，10 秒预留保存；采集动作上限仍为显式 5000 步 |

这些差异说明原函数复用不等于整条行为已等价；也不能推断修复后所有任务都能成功。底盘、机构技能、任务绑定和输入观测模式没有在本轮扩大范围。

另以真实 cuRobo GPU worker 和已保存的原生场景验证了持物登记及显式刷新，确认规划器刷新后仍登记目标为已附着。该检查为零动作接口验证，不计任务成功。

## 本轮条件

- 精确读取 r10 `atomic65-r10-seed0` 中原先实际运行的同一 22 项配置，保留任务语义、pretrain、seed 0；另外 43 项不在本轮重跑。
- 第一个动作之前比较旧/新原生场景 XML、成功函数、动作布局，以及所有保存的初始物理数组（含 qpos、qvel、ctrl、act、初始时间等）；误差上限 `1e-12`，不一致则停止该回合。
- GraspGen 每回合重新推理，不复用旧候选池或旧成功；每任务仅运行一个初态核对通过后的策略回合，内部保留原有有限抓取重试。
- 四张空闲 24 GB RTX 4090，每卡两个隔离会话。运行期间不修改 actor；成功和失败均保存视频、HDF5、阶段与原始结果。
- 仍使用仿真实例分割、物体位姿和完整几何作为 teacher 信息。原生 horizon 和成功函数不变，超过原生步数的成功单列。

这是一组组合修复的工程对照：初态相同，但重新推理的抓法仍可能不同，墙钟预算也改变，不能将成功率差异当作某个单独改动的消融结果。每任务一个初态不代表多初态平均成功率。

## 初态重建补充

同 seed 的 `PickPlaceSinkToCounter` 原生重置得到与旧回合左右对调的容器及干扰物区域；场景 XML 和随机数状态相同，完整物理数组不同。严格初态门禁拒绝了两次零动作初始化，视频与原始记录另存 `initialization_rejections`。重建后全部初始数组以 `1e-12` 容差核对通过，随后只运行一次策略，不按策略结果重试。原始计划保存在 `MATRIX.original.json`，计划扩展与恢复清单留档；不能再声称总共仅启动过 22 次进程。初始化重建脚本及摘要随实验产物保留，不改变冻结 actor 或三个执行工具。

## 最终结果

| 同初态 22 项 | 旧 r10 | 新 r13 |
| --- | --- | --- |
| 5000 步采集预算下完整成功 | 4/22（18.2%） | 4/22（18.2%） |
| 原生 horizon 内完整成功 | 2/22 | 1/22 |

**整体成功占比没有提升，原生预算内成功数反而减少，不能据此声称迁移已修好或已具备稳定泛化。** 新增成功为 `PickPlaceSinkToCounter`；原成功 `MakeIcedCoffee` 本轮在抬升被拒绝。其余成功为 `CheesyBread`（676 步、原生预算内）、`PickPlaceCounterToSink`（902 步）和 `PickPlaceCounterToStandMixer`（820 步）；水槽到台面为 948 步。两次零动作初始化拒绝不计策略回合，原始记录、录像与恢复脚本全部留档。

剩余 18 项：8 项抓取候选筛选未通过或搜索耗尽，5 项抬升时起点被规划器拒绝，4 项用完总时间预算，1 项目标不可见。4 项超时中，2 项通过了实际抬升保持，2 项未通过；不能统一解释为 GraspGen 抓不住。12 项发生真实闭合，6 项至少一次通过抬升保持。完全相同起点的全局拒绝结果复用了 342 次，未放宽原生碰撞检查。

所有 22 项初态、任务与源码核对通过；21 项可见目标的首份点云与旧版逐点相同，21 个新候选池均不同，合计重新调用 GraspGen 22 次。MakeIcedCoffee 实际选取的抓法相差约 4.87 mm、4.79°；这说明输入抓法不同，不证明退步一定由随机性造成。当前是多项修复、随机候选和预算一起变化的工程对照。

22 段新视频全部通过解码和 N 动作/N+1 观测对齐检查，旧版 22 段视频仍匹配原解码审核的 SHA256；离线 HTML 内嵌新旧 44 段视频（约 30 MB）。80 个 actor 文件及三个冻结执行工具在实验中保持不变。机读结果见 [验证摘要](../../migration/robocasa/VALIDATION_PICKPLACE22_20261112.json)。完整视频、HDF5、原始结果和初始化拒绝记录保留在实验目录；大产物不提交 Git。

日期：2026-11-12。r10 保留为旧记录，r12 是独立修复版本，不用新结果覆盖旧失败。r12 actor 指纹为 `90259b9c07c6fd5f093756e63923959a7563330473f2c434dc15a8367f74c45e`，冻结代码提交为 `3ab206809600a8804cfd7dd35c152b5a282cf8b9`。

## 已修正的差异

| 项目 | r10 的差异 | r12 的处理 |
| --- | --- | --- |
| 持物登记 | 局部 MuJoCo 已按持物预演，但向 cuRobo 登记附件延后到抬升成功后；4 个失败的抬升回退记录均显示未附着 | 在抬升规划前登记附件，抬升保持后再按实测位姿刷新；每次保存 `PRE_LIFT_CONTEXT.json` |
| 持物刷新 | 原版在抬升保持后显式 detach/attach 更新相对位姿，r11 首批漏掉 detach | 刷新规划几何时先 detach 再 attach，物理夹爪持续闭合；增加严格 worker 协议回归与 GPU 接口验证 |
| 离开源支撑 | 全局抬升回退没有传递原版的源支撑许可 | 合并初始及闭合后的实际接触，过滤为场景中真实的支撑几何，仅在全局抬升回退传递；原生完整路径检查仍拒绝机器人/环境碰撞 |
| 放置朝向 | 原版容器放置默认最多 4 个物体朝向，映射后的列表没有保留该上限 | 从原 LIBERO 有效默认值读取并验证统一上限，按原顺序保留最多 4 个朝向；原搬运高度/偏航/放置算法继续复用 |
| 相同起点反复拒绝 | 3 个超时任务从相同关节起点分别得到 157、120、36 次全局无效起点拒绝 | 仅对完全相同的完整场景、机器人/手指状态、附件及接触配置复用无效起点结果；每个目标仍执行原生局部回退。状态、场景或接触配置改变后重查，不缓存目标相关的 IK 失败 |
| 运行预算 | 原 LIBERO 单物体抓放允许 1200 秒，本轮 r10 只有 900 秒 | 统一恢复 1200 秒总上限，其中 1190 秒用于工作，10 秒预留保存；采集动作上限仍为显式 5000 步 |

这些差异说明原函数复用不等于整条行为已等价；也不能推断修复后所有任务都能成功。底盘、机构技能、任务绑定和输入观测模式没有在本轮扩大范围。

另以真实 cuRobo GPU worker 和已保存的原生场景验证了持物登记及显式刷新，确认规划器刷新后仍登记目标为已附着。该检查为零动作接口验证，不计任务成功。

## 本轮条件

- 精确读取 r10 `atomic65-r10-seed0` 中原先实际运行的同一 22 项配置，保留任务语义、pretrain、seed 0；另外 43 项不在本轮重跑。
- 第一个动作之前比较旧/新原生场景 XML、成功函数、动作布局，以及所有保存的初始物理数组（含 qpos、qvel、ctrl、act、初始时间等）；误差上限 `1e-12`，不一致则停止该回合。
- GraspGen 每回合重新推理，不复用旧候选池或旧成功；每任务外层只跑一次，内部保留原有有限抓取重试。
- 四张空闲 24 GB RTX 4090，每卡两个隔离会话。运行期间不修改 actor；成功和失败均保存视频、HDF5、阶段与原始结果。
- 仍使用仿真实例分割、物体位姿和完整几何作为 teacher 信息。原生 horizon 和成功函数不变，超过原生步数的成功单列。

这是一组组合修复的工程对照：初态相同，但重新推理的抓法仍可能不同，墙钟预算也改变，不能将成功率差异当作某个单独改动的消融结果。每任务一个初态不代表多初态平均成功率。

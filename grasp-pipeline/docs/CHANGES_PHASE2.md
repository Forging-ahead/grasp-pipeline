# 第二阶段具体改动

## 代码整理

- 从冻结 v10 建立独立 `grasp-pipeline/`，原开发目录、冻结副本和历史结果保留。
- 将原平级源码按策略、模型、规划、控制、点云、LIBERO 适配和公共工具拆成目录，更新所有内部导入。
- 将完整任务驱动放到 `apps/libero/`，原单任务 CLI 放到 `runtime/legacy_cli.py`。
- 修正模块移动后两个工作进程的模块名和 `PYTHONPATH`，RPC 协议保持原样。
- 将原测试保留在 `tests/v10/`，同步其模块导入与 RPC 子进程源码路径。
- 旧测评的运行环境准备、队列、报告和打包共 11 个脚本，独立保存于 `tools/legacy_evaluation/`；它们仍是原测评参考，不接入新默认入口。

## 配置和运行

- 任务清单原样保存到 `configs/libero/tasks.v10.json`。
- 原驱动中 15 个静态覆盖值移到 `configs/policy/v10_overrides.json`，四个 GPU/初态字段仍由原命令行绑定。
- 外部路径集中到 `configs/runtime/paths.server.json`，允许独立的部署路径文件，不允许混入策略参数。
- 新增轻量入口 `run.py`：列任务、显示有效配置、运行完整任务、执行前预览，以及显式调用旧单任务诊断。
- 输出默认统一到本目录的 `runs/<tag>/<task_key>/`，可显式指定根目录；仍拒绝复用已有任务输出。

## 源码追溯

模块移动后，源码指纹改为递归记录新相对路径，避免只记录顶层文件而遗漏模型、规划或控制代码。driver 指纹会反映整理后的新文件；不能把它冒充为原 v10 文件哈希。

`migration/V10_RELOCATION.json` 逐项保留原路径、新路径、前后指纹和机械替换内容。核验工具从冻结文件重新应用这些替换，要求与当前文件逐字节一致，再独立比较全部任务有效配置。

## 保持不变的部分

任务阶段顺序、抓取候选生成与筛选、放置和搬运目标搜索、碰撞模型、预检、限位处理、OSC 跟踪、夹爪操作、阶段退出和原始任务成功判定均沿用原算法。GraspGen 权重、cuRobo 版本及外部源代码未修改。

此次不新增 benchmark 技能、不优化失败任务、不重跑 130 条轨迹；原 v10 的 88 个最终条件满足、86 个管线完整成功及 85 个排除已知顺序问题后的候选成功轨迹仍是历史测评口径。

本次只运行 CPU 回归与结构、配置检查。它们验证重排和接口接线，不替代未来的 GPU 实际任务回归。

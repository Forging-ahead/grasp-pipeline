# LIBERO 机构接触与反馈控制迭代（2026-11-13）

本轮继续改进依赖仿真真值和手写几何规则的 code policy，覆盖抽屉、微波炉、炉灶、推移，以及相关机构取放复合任务。GraspGen 权重、评分顺序、cuRobo 官方实现和 LIBERO 官方资产未修改。

执行源码冻结为 `3e87a4a7fb212f996950408f6e244fce50a9822a`。后续文档提交不改变这个执行版本。结果只取该冻结版的新回合，不把开发版成功补进统计。

## 发现与修复

1. **预检与真实夹爪状态不一致。** 原机构整段预检保留张开的手指，真实运动先闭爪。现在先从实际开口检查静态双侧接触，再用闭合手指预检机构运动；真实执行仍检查持续夹持力。
2. **执行阶段把正在移动的门当成静止障碍。** 原整段预检已同步门运动，但短程执行预检仍固定旧门角。现在两处都在保存/恢复的仿真快照内同步机构；实际控制的碰撞检查不改变。
3. **无法用同一次夹持覆盖整个开门范围。** 圆柱把手的轴向自由度现在同时用于接近、进入把手和机构运动；仍失败时有限次分段松手、退让、重夹。每段按真实关节进度验收。
4. **关闭并不总需要夹住把手。** 在原方案不可行时，对活动面板生成闭合手指推闭候选。仅给手指与所选活动机构接触的权限，柜体、邻物、手掌及机械臂仍参与原检查。推点每次根据当前面板几何重新计算。
5. **收尾动作被容差吞掉，或平移机构受过严角度要求限制。** 门的末段按剩余位移收紧容差；滑动抽屉保留原有姿态容差。达到原始官方条件可以停止接触伺服，之后仍要退让、静置、复查。
6. **“已打开”与“足以执行下一阶段取放”混用。** 独立开门采用官方区间内较近的目标；需要取放通行时，按官方开度区间的中点验收，不仅检查 Open 谓词。已开得更大时不反向关小；重夹也不能因较早达到 Open 阈值而提前结束。
7. **退让方向及规划衔接。** 把手退向跟随原接近侧和机构运动，而非直接采用可能已经滚转的当前腕轴。补充经检查的退向与旋转自由度。推盘子后返回入场时已验证的高度；全局规划起点无效时，不再把同一错误当作多个不同终点重复尝试。
8. **离线失败状态难以复现。** 原 XML 在重置前保存，不能完整表达固定柜体在重置时对编译模型的修改。现在保存重置后的 XML、嵌入资产的同版本 MuJoCo 二进制模型、双精度模型参数，以及最终完整积分输入。原实际规划一直读取实时几何，旧 XML 记录问题不能当作原规划失败原因。

这些修改按关节类型、真实几何、开关区间及阶段前置条件工作，没有新增按任务名指定的世界坐标。运行清单中的任务名只用于选择实验对象。

## 共享参数与边界

本策略仍包含经验参数：把手静态接触对称性阈值、轴向自由度附近的关节余量、最多四段的重夹预算、有限面板采样、4 mm 级推动增量、伺服容差和退出预算等。它们是机器人/机构级规则，不是逐任务拟合的固定终点。

预检检查运动学可行性，不能保证摩擦、夹持或接触动力学。机构运动成功后，后续刚体抓放仍可能失败。仿真真值、语义把手、关节元数据和现有 Panda 控制接口仍是当前条件；迁移时应复用本分支规则并适配这些接口。成功轨迹仍需结合指令过程、接触质量和学生观测条件审核，不能直接把成功数当成可用 SFT 数据数。

二进制模型用于相同 MuJoCo 版本的几何/物理状态重放；它不包含 Python 控制器全部内部状态。旧失败回合只记录较少积分输入，因此本轮从旧状态进行的组件诊断不等同于逐位一致的完整控制器续跑。最终统计均来自官方初态重新运行。

## 尚未解决与下一步

- **狭窄处仍接近不了。** 下层抽屉等任务的候选在现有碰撞检查、局部 IK 或进入把手阶段被拒绝。下一步要区分真实相撞、代理几何过于保守、局部求解器没找到路径，再决定精化几何还是增加接近路径搜索，不能直接删障碍物。
- **开门重夹的衔接仍会失败。** 微波炉已被部分打开，但释放/重夹时 cuRobo 的代理球仍与门板重叠，当前起点被拒绝。这是模型与接触退出衔接的问题证据，不足以证明物理上没有路径。下一步应从同一失败状态核对精确接触与代理球，再增加经过检查的脱离与重规划。
- **机构通过不等于整条复合任务通过。** 有些任务已开门或关抽屉，但后续 GraspGen 候选未通过可达性检查，或者抬升规划失败；这些仍按整任务失败记录。当前没有增加此前暂缓的抓取方向去重或抬升前瞻。
- **完成轨迹仍须审核接触质量。** 20 Hz 记录到的非手指机构法向力超过 0.1 N 时标记人工复核，保留任务完成结果，但不直接放入高质量训练集。原几何容差内的轻微穿入也可能产生实际接触力；未触发此标记不等于通过了全场景、所有积分子步的质量审核。下一步需补充接触力约束与更高频的采集审核。

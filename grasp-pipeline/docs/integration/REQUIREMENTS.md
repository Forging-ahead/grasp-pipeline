# 接入前要提供的数据和能力

接入开发从 `libero` 分支开始，优先继承已有代码策略、规划与控制实现；下面列出的是新环境需要提供的输入和接口，不是要求重新编写整条管线。详见[基线继承要求](BASELINE_FIRST.md)。

先填写 [接入设计单](templates/integration_spec.example.json)。模型权重、机器人资产、任务资产和三个进程环境不随代码目录完整打包，接入方需要准备并记录版本。机器人数、动作维度、控制频率和四元数顺序都从实际环境读取，不能沿用 LIBERO 常量。

## 共同输入

| 输入或能力 | 接入方提供什么 | 验收证据 |
| --- | --- | --- |
| 环境与初态 | create/reset/observe/step/close；任务、seed、初态标识、控制周期、原生终止/截断 | 同配置重置得到一致初态；observe 不推进物理，阶段之间不 reset |
| 任务语义 | 原任务文本、原生目标、实体与区域 ID、前置条件及顺序要求 | TaskSpec 与原判定对应；未知谓词和未实现技能明确报出 |
| 机器人状态 | 命名关节及顺序、位置/速度、手指状态、基座与实际 TCP 位姿 | 与环境测量及模型 FK 对齐，原始状态不被裁剪或补零 |
| 机器人模型 | 运动学、关节限位、碰撞几何、夹爪、基座、TCP 和 GraspGen 参考点 | 多姿态 FK 对照；碰撞模型包含实际使用的机构与静止机械臂 |
| 环境碰撞模型 | 所有相关障碍物、支撑面、目标几何、位姿、网格资源及更新标识 | 场景叠加可见；尺寸和资源正确，未知空间有显式处理 |
| 局部规划/预检 | 对应引擎的 IK、接触查询、路径采样和无副作用预演 | 障碍会拒绝路径，预演前后真实状态/时间/控制输入一致 |
| 控制与夹爪 | 路点到原生动作的映射、闭环误差、开/关/保持语义、异常和终止处理 | 空载位姿移动和夹爪实测；原生终止后不继续 step |
| 原生成功 | 本 benchmark 的原始最终判定，必要时子目标查询 | 读取环境结果，保留“原生 true 但管线中断”等组合 |
| 记录 | 动作前后观测、状态、阶段、计划、视频、错误与资源指纹 | N 动作对应 N+1 状态，关键点与正确观测关联 |

## 按技能补齐输入

| 技能 | 额外必需条件 | 缺少时如何处理 |
| --- | --- | --- |
| 抓取并放置 | 目标点云、目标和目的地几何、放置区域、支撑接触、持物相对变换 | 先补感知/几何；不能把缺点云、缺目的地或规划拒绝归为抓取模型失败 |
| 推移 | 物体位姿、支撑面、接触点/方向、目标区域、连续接触与目标判定 | 无推移技能则标 unsupported，不替换成抓放后冒称同任务 |
| 拉门/抽屉/旋钮 | 当前关节 q、类型/轴/锚点/限位、把手几何、原生开关规则 | 不要求先调用 GraspGen；需要相应接触技能和约束运动，单一末端终点不够 |
| 多物体与复合任务 | 每个子目标、依赖、明确顺序、物体/机构更新及阶段间持物状态 | 保持同一回合，单独核验指令顺序；不能只看最后谓词 |

当前 `task_policy.schedule` 处理 on/in/open/close/turnon/turnoff，并含英文 push 关键词规则。它没有任意自然语言任务理解能力。其他谓词、any 目标语义、交接、导航、倒液体或柔性操作需要另行实现和验证，不能通过修改任务名称获得。

## 观测来源先选清楚

**teacher 模式**允许使用接入方明确提供的仿真实例掩码、实体位姿、完整几何和关节信息，所有使用项标记 simulator_truth。它适合本项目目前的成功轨迹采集目标，但结果必须写清输入条件。

这里描述的是实验输入模式，不代表目标 benchmark 的标准评估允许所有真值；官方分数需按其实际观测规则另行验证，teacher 与 sensor 结果分开报告。

**sensor 模式**由传感器/感知/估计/记忆提供目标和碰撞场景，保留时间与来源。只有单目 RGB 和机器人状态，不能直接满足现有抓放输入；仍需可靠的米制目标点云、目标定位及规划所需场景。当前代码没有自动补齐检测、分割、单目深度或重建服务。

目标点云可以由 RGB-D 与掩码反投影，也可直接由提供方给出世界坐标点。当前 GraspGen worker 至少需要 16 个有效点，再采样为 2048 点；阈值是现实现有条件，不代表稀疏点云一定能产生有效抓法。部分点云与完整几何输入应分开记录。

## 机器人和引擎是独立适配项

同为 MuJoCo 不等于控制器、对象注册和目标区域相同；同为七关节也不等于当前 Panda 模型可直接复用。更换机器人需要处理 `PandaMJCF`、命名关节、夹爪模型、碰撞表示、TCP 和控制，而更换引擎还需要替代 MuJoCo Jacobian、接触及状态恢复操作。

双臂/移动底盘必须完整描述主动关节及另一机械臂/底盘的碰撞影响。只选一只手时，也需固定并建模另一只手；不应把双臂动作截成七维后计为完整双臂任务适配。

## 版本和资源清单

交付时记录 benchmark、包装层和任务资产 commit/摘要；仿真、GraspGen、规划解释器及依赖；机器人与网格资产；相机配置；GraspGen 生成器/判别器配置与摘要；动作规格；原生预算；运行 seed/初态。已有三个进程的隔离方式可复用，环境依赖分别安装，按实际版本核验。

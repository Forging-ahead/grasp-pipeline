# 外部 benchmark 接入实施指南

这份指南供其他 benchmark 的维护者接入现有 GraspGen、code policy、cuRobo 与局部控制管线。我们提供代码、接口约定、参考与检查方法；接入方负责本环境适配和运行验证。本轮没有实现 RoboTwin、RoboCasa 适配。

## 先确认当前状态

当前可运行入口仍是 LIBERO、单 robosuite Panda。第三阶段的九类 Protocol 和 Schema 是接入约定，旧驱动尚未经这些接口调用。**实现接口后，还必须接通策略、规划、预检和执行的调用链；只换仓库路径或任务名字不够。**

`run.py` 目前只有 list、config、run、legacy 四个子命令，没有 benchmark 插件注册表、`--benchmark` 选择器或其他环境的运行入口。`readiness()` 当前固定读取 LIBERO teacher profile，也不是任意 benchmark 的通用验收器。

## 按这个顺序接入

| 步骤 | 接入方要做什么 | 文档 |
| --- | --- | --- |
| 1 确定范围 | 固定 benchmark commit、机器人、观测模式、任务和初态；先选一个单物体刚性抓放任务 | [输入与能力清单](REQUIREMENTS.md) |
| 2 列明差异 | 确定能复用什么，逐项定位环境/机器人/引擎相关代码 | [文件修改清单](FILE_CHANGES.md) |
| 3 形成设计 | 填写设计单，准备任务/能力/路径示例，明确新启动入口和依赖 | [配置与样例](CONFIGURATION.md) |
| 4 接通运行链 | 实现本环境的提供方和启动编排，替换直接访问 LIBERO/MuJoCo 的调用 | [文件修改清单](FILE_CHANGES.md) |
| 5 逐级验收 | 从静态数据、坐标、空载移动、单次抓取到完整任务，失败时停在对应层检查 | [调试与验证](DEBUG_VALIDATE.md) |
| 6 扩大任务覆盖 | 保留每次成功/失败、原生分数、实际后端和完整轨迹，再扩到关节及复合任务 | [结果与交付](RESULTS_HANDOFF.md) |

[RoboTwin 与 RoboCasa 差异说明](BENCHMARK_NOTES.md) 给出官方资料和本地 RPent 参考。RPent 是可选参考，不是本管线要求安装的依赖。

## 谁负责什么

| 我们已有的组件或约定 | 接入方必须补齐的部分 |
| --- | --- |
| GraspGen 官方 Panda 权重调用、点云采样和候选处理 | 目标身份/掩码/米制点云来源、夹爪兼容性和参考点标定 |
| 阶段目标、搬运和放置搜索的代码 | 本环境任务/区域语义、实体映射、前置条件与指令顺序，以及这些输入的调用接线 |
| 当前 Panda/cuRobo 和 MuJoCo 局部 IK 实现 | 实际机器人模型、引擎场景导出、局部 IK/预检后端及控制器映射 |
| 14 类数据包、来源和结果记录约定 | 本环境原生成功判定、终止规则、连续回合和完整数据记录 |
| LIBERO 参考、113 项既有 CPU 验证记录 | 新 benchmark 的接入测试、任务实验与独立成绩 |

## 完成接入的标准

接口字段通过、模型服务能启动、末端到位、物体被抬升、完整任务成功是不同层次。需要至少留下：可复现的环境和配置、一条连续的真实执行轨迹、原生任务判定、完整失败记录、实际规划/控制后端，以及必要的输入和坐标核验。

没有原生任务判定或没有真实动作时，不能只凭工具返回 success 声称已跑通 benchmark。没有完整观测与决策记录时，也不能直接声称轨迹已成为合格的 VLM SFT 数据。

本指南中的命令分为“仓库现有命令”和“接入方实现后才能执行的步骤”。所有拟新增文件与设计模板均明确标记，不含伪装成现成入口的其他 benchmark 命令。

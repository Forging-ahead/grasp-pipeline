# 配置来源与优先级

## 三类配置

| 文件 | 内容 | 本阶段处理 |
| --- | --- | --- |
| `libero/tasks.v10.json` | 最终 130 任务的原始清单与每任务配置 | 从冻结 v10 逐字节复制，未改动 |
| `policy/v10_overrides.json` | 原驱动里 15 个字面量覆盖参数 | 从 AST 提取，值和类型保留 |
| `runtime/paths.server.json` | 原服务器五个 actor 外部路径和一个仿真解释器路径 | 部署路径集中到一处，默认值与实测基线一致 |
| `examples/single_task.v10.json` | 原 `server.json` 示例 | 逐字节复制，仅供原单任务诊断入口使用 |

任务清单内仍保留其原路径字段以便核验；实际运行时由统一的部署路径覆盖这五个字段，迁移服务器不必逐条修改 130 个任务。

六个部署字段为 `libero_repo`、`grasp_repo`、`graspgen_python`、`graspgen_config`、`planner_python`、`simulation_python`。最后一个仅供启动器选择仿真解释器，不会新增到 actor 的任务配置里。

`runtime/paths.local.json` 为用户本地配置，已加入忽略规则。部署文件只接受上述六个绝对路径，混入抬升高度等策略参数会明确报错。

## 完整任务的实际优先级

1. 读取 `tasks.v10.json` 对应任务的 `config`。
2. 绑定 `--gpu` 到仿真、GraspGen、规划三个 GPU 字段，绑定 `--init`。
3. 应用 `v10_overrides.json` 的 15 个原值。
4. 应用选定部署文件中的五个外部路径。
5. 和原驱动一样，以目标物体暂作启动目的地；实际阶段再根据原任务目标设置目的物体、区域和关系。
6. 多物体布局和阶段内部配置覆盖保持原逻辑。

输出目录、tag 和部署路径属于运行设置，不修改候选搜索、几何、控制或成功判定参数。`--dry-run` 与 `config` 会显示启动阶段实际得到的配置。

## 哪些参数没有外移

这里只把原驱动的字面量覆盖独立出来。各模块中的技能默认值和数值常量继续保留在原函数位置，避免在目录整理时顺便改变逻辑。抬升高度、偏移、候选高度、控制容差等既有值均未调优。

原单任务 `legacy` 入口仍按显式 `--config` 和它自己的命令行覆盖工作，不会自动套用完整 130 任务的覆盖参数。若给 `legacy` 显式提供 `--paths`，部署文件会覆盖该单任务配置的五个外部路径。

后续如要修改策略参数，应建立新的参数版本及验证记录；本阶段配置不能用来声称新成功率。
